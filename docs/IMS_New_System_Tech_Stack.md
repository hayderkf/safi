# مكدّس النظام الجديد وقرارات المعمارية (Tech Stack & Decisions)

> **الحالة:** متّفق عليه (مسوّدة حيّة) · **التاريخ:** 2026-06-12 · **مرافق لـ:** `IMS_New_System_Founding_Vision.md`, `IMS_Technical_Challenges_Register.md`.
> جميع المكوّنات مفتوحة المصدر ورخصها **تساهلية تسمح بالبيع التجاري ومنتجاً مغلق المصدر** (لا حقوق متروكة/AGPL). النسخ المدفوعة (Temporal Cloud / React Flow Pro / Stately Studio) **اختيارية لا إلزامية**.

## قرارات معمارية بارزة (ADR-lite)

### DR-1 — محرّك تنفيذ سير العمل: Temporal أساسي، مع شرط رجوع للخيار ب
- **القرار:** اعتماد **Temporal (Python SDK، self-hosted، MIT)** كمحرّك التنفيذ.
- **السبب:** المجال امتثال/رقابة بعمليات طويلة الأمد ومواعيد وسجلّ تدقيق؛ الموثوقية **غير قابلة للتفاوض**، وTemporal يوفّر الديمومة/المؤقّتات/التعافي **جاهزة** وله Python SDK ومجاني.
- **⚠️ شرط الرجوع (Fallback Trigger):** عند ملاحظة **ضعف أداء Temporal** أو عبء تشغيلي غير مبرّر، **وبطلب صريح من المالك**، ننتقل إلى:
  **الخيار ب — مكتبة statechart بايثونية (`python-statemachine` / `transitions`) + طبقة ديمومة نبنيها** (snapshot → Postgres + مجدول مؤقّتات دائم + استئناف idempotent).
- **تمكين الرجوع بلا ألم:** نُبقي **طبقة تجريد لمحرّك سير العمل** (واجهة موحّدة) من اليوم الأول، فيكون التبديل محصوراً في الركيزة وحدها — **دون مساس** بمحرّر ReactFlow ولا بطبقة الذكاء/التنسيق (كلها فوق الركيزة ومحايدة لها).

### DR-2 — النموذج التوليدي: qwen2.5:14b افتراضياً (بعد PoC) خلف طبقة تجريد
- **القرار:** اعتماد **qwen2.5:14b موقعياً** نموذجاً افتراضياً للتطوير (Apache 2.0، سيادة بيانات كاملة).
- **الدليل (PoC 2026-06-20):** ولّد استمارات عربية بمستوى إنتاجي شمل البنى الصعبة (stepper متعدد الصفحات، جداول، مصفوفات، مجموعات متكررة، منطق شرطي)، وطابَق جودة gemma4:26b/31b بنحو **ضعف السرعة**؛ سكربت الاختبار: `poc_form_eval.py`، المخرجات: `poc_out/`.
- **التمكين:** طبقة تجريد المزوّد تُبقي Gemma 4 (26b/31b) وأي نموذج آخر قابلاً للتبديل؛ **Embeddings موقعية (BGE).**
- **التحسينات المتبقية قبل الإنتاج:** ضمان مخرَج بنيوي (structured output) + few-shot + اختبار الإسناد للبيانات الساندة.

### DR-3 — محرّر/تنفيذ منفصلان
- ReactFlow = **محرّر** (تصميم بصري)؛ محرّك التنفيذ منفصل تحته. لا يُخلط الاثنان. طبقة الذكاء والتنسيق **ملكيتنا** وتعلو الركيزة.

### DR-4 — البيانات الساندة = «سجلّ موارد معرفية مُسنَدة» (متعدّد الأنواع، حدّ الإسناد المغلق)
- **القرار:** القوائم الساندة ليست غايةً بذاتها، بل **النوع الأول** من سجلّ موارد معرفية محكوم يغذّي **الاستمارات** (ربط `dataSourceKey`) و**الذكاء** (تأسيس/RAG) معاً.
- **المظروف الموحّد لكل مورد:** إسناد (مصدر/ثقة/إصدار) + حوكمة (حالة `is_active`/مراجعة `reviewed_by`/اعتماد) + صلاحية. **الحمولة تختلف بالنوع** (`kind`): `list` الآن؛ ولاحقاً `document`/`dataset`/`feed`/`corpus` — تُضاف **عند حالة استخدام حقيقية فقط**.
- **حدّ الثقة للذكاء:** هذا السجلّ هو تجسيد «الإسناد المغلق» — النموذج لا يؤسّس إلا على موارد **معتمدة** فيه.
- **الإيقاع (ضدّ الإفراط):** لا يُجرَّد المظروف الموحّد قبل وجود **نوعين حقيقيين**؛ يُستخرج «الموظِّف» (الكتالوج العام) عند إدخال `document` في مرحلة RAG (٦). حتى ذلك الحين: `kind=list` بذرةً على القائمة.
- **الآن:** تمتين النوع `list` — تفرّد `(list_key, value_key)` + حذف ناعم `is_active` + تسجيل المراجعة — وإدخال **Excel** (يمرّ بمراجعة بشرية).
